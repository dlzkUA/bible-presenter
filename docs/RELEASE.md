# Как выпустить версию на GitHub — для тех, кто делает это впервые

Итог: на странице GitHub Releases лежат установщик для Windows (`.exe`) и один `.dmg` для любого Mac — и на Intel, и на Apple Silicon (M1/M2/M3/M4). Уже установленные программы находят новую версию сами и обновляются.

Облачной сборки (CI) у проекта нет: всё собирается на ваших компьютерах. Поэтому Windows-версию собирают на Windows, а Mac-версию — на Mac. Mac подойдёт любой, Intel тоже. Получается один «универсальный» `.dmg`, который работает на всех Mac.

## Что понадобится

- компьютер с Windows 10/11 — на нём вы и так работаете с проектом;
- Mac на macOS 11 или новее; Intel годится;
- аккаунт на GitHub;
- файл ключа обновлений `bible-presenter-updater.key`. Я передавал его отдельно от проекта. Храните копию в менеджере паролей или на флешке: без него установленные программы не примут обновление;
- интернет: при первой сборке скачивается около 1–2 ГБ инструментов и библиотек.

---

## Часть 1. Один раз: положить проект на GitHub

Пропустите эту часть, если репозиторий уже есть и проект в нём.

1. Скройте свою почту, чтобы она не попала в историю проекта.
   - На github.com откройте фото профиля → **Settings** → **Emails**.
   - Включите **Keep my email addresses private** и **Block command line pushes that expose my email**.
   - Ниже на той же странице появится адрес вида `12345+имя@users.noreply.github.com`. Он понадобится в шаге 3.
2. Установите **GitHub Desktop** с desktop.github.com и войдите в свой аккаунт.
3. Укажите в GitHub Desktop скрытую почту.
   - Откройте **File → Options → Git** (на Mac: GitHub Desktop → Settings → Git).
   - В поле Email выберите адрес `…@users.noreply.github.com`.
4. Добавьте папку проекта.
   - Распакуйте `bible-presenter.zip` в папку вне OneDrive, например `C:\Projects\bible-presenter`. Документы и Рабочий стол часто синхронизируются с OneDrive, а при сборке там появляются гигабайты временных файлов: синхронизация их блокирует, и сборка падает.
   - В GitHub Desktop выберите **File → Add local repository** и укажите эту папку.
   - Программа скажет, что это ещё не репозиторий. Нажмите **create a repository** → **Create repository**.
5. Нажмите **Publish repository**.
   - **Снимите** галочку «Keep this code private». Автообновления скачиваются только из открытого репозитория.
   - Ничего личного туда не попадёт. Ваши песни и настройки хранятся в другой папке (`%APPDATA%\BiblePresenter`), а ключ исключён из репозитория.

## Часть 2. Один раз: подготовить Windows

1. Установите **Node.js**: на nodejs.org скачайте версию **LTS** и установите со всеми настройками по умолчанию.
2. Дважды щёлкните `build-windows.cmd` в папке проекта.
   - Если Windows покажет «Windows защитила ваш компьютер», нажмите **Подробнее** → **Выполнить в любом случае**.
   - Если Rust не установлен, скрипт откроет rustup.rs.
3. Установите Rust.
   - Скачайте `rustup-init.exe` и запустите.
   - Когда он предложит установить Visual Studio, выберите **1** (Quick install) и нажмите Enter.
   - В установщике Visual Studio ничего не меняйте и нажмите «Установить». Это займёт 10–20 минут.
   - Затем в чёрном окне rustup появится меню с вариантами 1, 2, 3. Нажмите **1** и Enter.
   - Дождитесь надписи **Rust is installed now. Great!** и только после неё закрывайте окно. Если закрыть раньше, установка останется недоделанной.
4. Закройте все чёрные окна. Перезапустите GitHub Desktop, чтобы он увидел Node.js.

С этого момента перед каждой отправкой в `master` (кнопка **Push origin**) сами запускаются проверки. Подробности в части 6.

## Часть 3. Выпуск версии: Windows

1. **Номер версии.** Для первого выпуска (3.0.0) ничего менять не нужно. Для следующих поставьте одинаковый номер в двух файлах:
   - `package.json`, строка `"version": "3.0.1"`;
   - `src-tauri/Cargo.toml`, строка `version = "3.0.1"` в самом верху.
2. **Отправьте изменения.** В GitHub Desktop напишите пару слов в поле Summary → **Commit to master** → **Push origin**.
   - Перед отправкой пройдут проверки. Первый раз это займёт 5–10 минут, потом около минуты.
   - На несколько секунд откроются и закроются окна программы. Это нормально.
3. **Соберите установщик:** дважды щёлкните `build-windows.cmd`.
   - **Адрес репозитория.** Скрипт спросит его только в первый раз и только если не определит сам. Вставьте адрес вида `https://github.com/ваш-логин/bible-presenter` и нажмите Enter.
   - **Ключ обновлений.** Скрипт сам ищет `bible-presenter-updater.key` на Рабочем столе, в Загрузках и Документах. Если не найдёт, перетащите файл мышкой в чёрное окно и нажмите Enter.
     - Скрипт сразу проверит, что ключ тот самый.
     - Если просто нажать Enter, программа соберётся, но обновляться сама не сможет.
   - **Сборка** идёт 10–20 минут в первый раз и 3–5 минут потом.
   - **Результат.** Откроется папка `release\v3.0.0` с тремя файлами:
     - `Bible-Presenter_3.0.0_x64-setup.exe`;
     - `latest.json`;
     - `latest.yml`.
4. **Только в первый раз:** скрипт записал адрес обновлений в `src-tauri/tauri.conf.json` и `package.json`. Отправьте это изменение: **Commit to master** → **Push origin**.

## Часть 4. Создать релиз на GitHub

1. Откройте страницу репозитория → справа **Releases** → **Draft a new release**. Если релизов ещё нет, кнопка называется **Create a new release**.
2. Задайте тег.
   - Нажмите **Choose a tag**, введите `v3.0.0` — с буквой v, тот же номер, что в package.json.
   - Нажмите **Create new tag: v3.0.0 on publish**.
3. **Release title:** `Bible Presenter 3.0.0`.
4. В описание можно вставить, например:
   `Windows — скачайте файл, который заканчивается на -setup.exe. Mac (Intel и Apple Silicon) — файл .dmg. Дальше программа обновляется сама.`
5. Перетащите в поле «Attach binaries» три файла из `release\v3.0.0`:
   - `.exe`;
   - `latest.json`;
   - `latest.yml`.
6. Внизу оставьте галочку **Set as the latest release** и нажмите **Publish release**.

С этого момента Windows-версия опубликована. Компьютеры с версией 2 и с версией 3 начнут обновляться.

## Часть 5. Выпуск версии: Mac (Intel или Apple Silicon)

GitHub Desktop на Mac ставить не нужно: хватит браузера, Терминала и файла ключа. Выбирать между Intel и Apple Silicon тоже не нужно: сборка универсальная.

Перед началом убедитесь, что Windows-версия опубликована как релиз (часть 4), а изменения с адресом обновлений отправлены кнопкой Push origin. Mac берёт проект с сайта, и без этого он получит старые файлы.

### Шаг 1. Скачать проект на Mac

1. Откройте Safari и зайдите на страницу репозитория: `https://github.com/ваш-логин/bible-presenter`.
2. Нажмите зелёную кнопку **Code** → **Download ZIP**.
3. Откройте Загрузки и дважды щёлкните архив. Рядом появится папка `bible-presenter-master` (или `-main`).

### Шаг 2. Перенести ключ на Mac

Нужен файл `bible-presenter-updater.key`. Перенесите его через AirDrop, флешку или менеджер паролей и положите в **Загрузки** или на **Рабочий стол**: там скрипт найдёт его сам. Не отправляйте его по почте и в мессенджерах: ключ даёт право выпускать обновления для всех установленных копий.

### Шаг 3. Запустить сборку

1. Нажмите ⌘+Пробел, наберите «Терминал» и нажмите Enter.
2. Напечатайте слово `bash` и **пробел** после него. Enter пока не нажимайте.
3. Откройте в Finder папку проекта и перетащите файл `build-mac.command` в окно Терминала. Путь к файлу подставится сам.
4. Нажмите Enter.

Через `bash` нужно потому, что скачанный файл Mac не даст запустить двойным щелчком.

### Шаг 4. Если скрипт просит что-то установить

В первый раз скрипт останавливается и просит доустановить недостающее. Это нормально. После каждой установки закройте Терминал, откройте новый и повторите шаг 3.

- **Инструменты разработчика Apple.** Появится окно. Нажмите **Установить** и подождите 5–20 минут.
- **Node.js.** Откроется сайт nodejs.org. Скачайте версию **LTS** (файл `.pkg`), откройте его и нажимайте «Продолжить» до конца.
- **Rust.** Скрипт поставит его сам за 1–3 минуты.

### Шаг 5. Дождаться сборки

Первый раз она идёт 15–30 минут, на Intel Mac дольше. Терминал не закрывайте и не давайте Маку уснуть. Мак может спросить разрешение на доступ к папкам или на управление Finder: нажимайте **Разрешить**. Если нажали «Не разрешать», сборка упадёт на этапе `.dmg`; как это исправить, написано в таблице в конце.

### Шаг 6. Результат

В конце откроется папка `release/v3.0.0` с тремя файлами:

- `Bible-Presenter_3.0.0_universal.dmg` — установщик для Mac, один и для Intel, и для M1–M4;
- `Bible-Presenter_3.0.0_universal.app.tar.gz` — из него Mac обновляется сам;
- `latest.json` — в нём уже обе системы: скрипт скачал Windows-запись из релиза и добавил Mac.

Если скрипт пишет, что Windows-версию в релизе не нашёл, значит, часть 4 не опубликована. Опубликуйте её и повторите шаг 3.

### Шаг 7. Добавить файлы в релиз

1. Откройте в Safari страницу релизов `https://github.com/ваш-логин/bible-presenter/releases` и войдите в свой аккаунт GitHub.
2. Нажмите на карандаш (**Edit**) у релиза `v3.0.0`.
3. У старого `latest.json` нажмите крестик, чтобы удалить его.
4. Перетащите в окно браузера три файла из папки `release/v3.0.0`.
5. Нажмите **Update release**.

### Шаг 8. Проверить

Откройте в браузере `https://github.com/ваш-логин/bible-presenter/releases/latest/download/latest.json`. В тексте должны быть `windows-x86_64`, `darwin-x86_64` и `darwin-aarch64`. Затем откройте `.dmg` и перетащите программу в Applications. При первом запуске щёлкните по ней правой кнопкой и выберите **Открыть**: программа не подписана Apple.

**Хочется только Intel и побыстрее?** Добавьте `--mac intel` в конец команды из шага 3 (после пути к файлу, через пробел). Но тогда Mac на Apple Silicon не получат обновлений через программу. Универсальная сборка лучше.

## Часть 6. Проверки перед отправкой в master

Облака нет, поэтому всё проверяется у вас при **Push origin** в `master`. Если проверка не прошла, отправка останавливается, а GitHub Desktop показывает, что именно сломалось. Пришлите мне этот текст.

Что проверяется (около минуты):

- **Переводы:** у всех 27 языков одинаковый набор фраз.
- **Синтаксис** всех скриптов страниц.
- **Тесты бэкенда:**
  - импорт Библии (Zefania, OSIS, битый файл) и поиск по фразе;
  - импорт песен и тем ProPresenter;
  - сервер пульта для телефона: PIN, пауза после неверных PIN, ключ на каждой команде и картинке;
  - сервер трансляции для vMix/OBS и сцены.
- **Сквозной тест.** Настоящая программа на пустой временной папке проверяет четыре сценария, без которых служение не пройдёт:
  - ссылка на стих выводится на проектор;
  - вставленная песня делится на слайды, «Далее» листает;
  - PDF импортируется и показывается;
  - телефон подключается по PIN и нажимает «Далее».
  
  Ваши песни и настройки тест не трогает.

Чтобы запустить проверки без отправки, откройте папку проекта в терминале и выполните `npm run check`.

Если Windows спросит, разрешить ли `bible-presenter` доступ к сети, можно нажать «Отмена»: тесты работают внутри компьютера.

## Следующие версии — коротко

1. Поменяйте номер в `package.json` и `src-tauri/Cargo.toml`, затем Commit → Push (проверки пройдут сами).
2. Запустите `build-windows.cmd` и создайте новый релиз `v3.0.1` с файлами `.exe`, `latest.json` и `latest.yml`.
3. На Mac скачайте свежий ZIP проекта, запустите `bash build-mac.command`, затем Edit релиза: замените `latest.json`, добавьте `.dmg` и `.app.tar.gz`.

Установленные программы скачают обновление в фоне и поставят его, когда их закроют.

Библиотеки для сборки скрипт держит в отдельной папке (`C:\BiblePresenter-build` на Windows, `/Users/Shared/BiblePresenter-build` на Mac). Так в программу не попадает имя вашей учётной записи. Первая сборка после этого изменения скачивает библиотеки заново и идёт дольше. В конце скрипт сам проверяет готовую программу и останавливается, если находит в ней путь с вашим именем.

## Если что-то пошло не так

| Сообщение | Что делать |
|---|---|
| «Версии не совпадают» | Поставьте одинаковый номер в `package.json` и `src-tauri/Cargo.toml`. |
| «link.exe not found» (Windows) | Не установлен Visual Studio: запустите `rustup-init.exe` ещё раз и выберите 1. |
| «xcrun: error» (Mac) | Не установлены инструменты Apple: запустите сборку ещё раз и нажмите «Установить» в появившемся окне. |
| «Ключ не подходит» / «ключ не от этой программы» | Нужен именно `bible-presenter-updater.key`, а не `.pub` и не другой ключ. |
| Mac: сборка падает на `aws-lc-sys` или на ошибках `clang` / `assembler` | Универсальная сборка компилирует программу для Intel и Apple Silicon, и на старом Mac вторая архитектура может не собраться. Скрипт сам предложит собрать только для вашего Mac: нажмите Enter. Чтобы собрать обе, обновите инструменты Apple (Системные настройки → Основные → Обновление ПО). Журнал сборки сохраняется в `release/build-log.txt`. |
| Mac: сборка падает на «Failed running AppleScript» или «bundle_dmg» | Терминалу запрещено управлять Finder. Откройте Системные настройки → Конфиденциальность и безопасность → Автоматизация → Терминал и включите Finder. |
| Mac: «программа повреждена» или «не удаётся проверить разработчика» | Щёлкните программу правой кнопкой → **Открыть**. На macOS 15: Настройки → Конфиденциальность и безопасность → **Всё равно открыть**. |
| Программы не обновляются | Репозиторий должен быть открытым. В релизе должен лежать `latest.json`, а релиз должен быть отмечен как Latest. |
| «В собранной программе есть путь с именем пользователя» | Не загружайте эти файлы. Пришлите `release/build-log.txt`. |
| Ключ потерян | Обновлять уже установленные копии будет нельзя: только переустановкой. Новый ключ делается по инструкции в README. |

Никогда не загружайте файл `.key` на GitHub, в чаты или в почту. Проект его не хранит: скрипты только читают файл, на который вы указали, во время сборки.
